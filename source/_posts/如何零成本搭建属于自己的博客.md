这是本博客的第一篇文章，主要记录其搭建的完整过程。

其实很早以前，我就萌生了拥有一个个人博客的想法。我并不期待自己能写出多么深刻或优秀的文章，也未曾打算通过博客获取什么收益，只是希望在互联网这片广袤的空间里，能有一块属于自己的、安静的角落，用以记录学习过程、零星思考，以及成长历程中的种种痕迹。

## 为什么重新搭建博客

我第一次接触博客是在高中之前。高中时我曾搭建过一个 WordPress 博客，当时通过 Azure 学生认证获取了一年的免费云服务器。有了服务器之后，我部署了 WordPress，尝试修改主题、配置插件，把它当作自己的个人网站来打理。但进入高中后，学业压力渐增，没有太多时间继续维护，服务器、网站与数据最终都逐渐停摆，此前积累的内容也随之丢失。

直到现在大三阶段，随着新技术的接触，我再次萌生了搭建博客的念头。这一次，我希望采用更简单、更可持续的方式——不愿再为服务器安全、Linux 环境维护、数据库备份等问题耗费精力，也不希望为博客长期支付费用。

所以最终选择了：

> 静态博客 + GitHub Pages + 自动化部署

这种更适合个人长期维护的方案。

---

# 方案选择

目前搭建个人博客的方式有很多，例如 WordPress、Halo、Hugo、Hexo、Jekyll 等。经过比较，我最终选择了 Hexo。

原因很简单：Hexo 本身是一个静态博客生成器。我只需使用 Markdown 编写文章，由 Hexo 将文章转换成网页，再将生成的静态文件部署出去。整个过程无需数据库，也无需后端服务，对个人博客而言足够轻量。

最终使用的方案如下：

- Hexo：博客生成框架
- Yilia Plus：博客主题
- GitHub Pages：网站托管
- GitHub Actions：自动构建部署
- Giscus：评论系统

整个博客不需要购买服务器，也不需要购买域名，成本为零。

---

# 安装 Hexo

Hexo 是一款基于 Node.js 的静态博客生成器，支持使用 Markdown 编写文章，并生成完整的静态网站。

## 环境准备

首先需要安装 Node.js 和 Git，并检查环境：

```bash
node -v
npm -v
git --version
```

---

## 安装 Hexo

通过 npm 安装 Hexo 命令行工具：

```bash
npm install -g hexo-cli
```

查看版本：

```bash
hexo -v
```

---

## 初始化博客

创建博客目录并初始化：

```bash
hexo init blog
cd blog
npm install
```

正常情况下，Hexo 会自动下载初始化模板。但在实际执行 `hexo generate` 时，遇到了网络错误，无法成功拉取 `https://github.com/hexojs/hexo-starter.git`。由于 GitHub 网络连接不稳定，初始化过程失败。后来我改为手动克隆仓库：

```bash
git clone https://github.com/hexojs/hexo-starter.git
```

然后重新安装依赖：

```bash
npm install
```

最终完成了初始化。

---

# 本地运行博客

生成网页并启动本地服务：

```bash
hexo generate
hexo server
```

访问 `http://localhost:4000` 即可看到本地博客。

---

# 配置博客主题

Hexo 默认主题较为简约，因此我选择了 Yilia Plus 主题。

安装主题：

```bash
git clone https://github.com/JoeyBling/hexo-theme-yilia-plus.git themes/yilia-plus
```

修改 Hexo 配置文件：

```yaml
theme: yilia-plus
```

重新生成：

```bash
hexo clean
hexo generate
```

之后博客页面便替换为新主题。

---

# 编写文章

Hexo 使用 Markdown 管理文章。创建文章：

```bash
hexo new "文章标题"
```

生成的文件位于 `source/_posts/` 目录下，文章结构如下：

```markdown
---
title: 文章标题
date: 2026-07-27
tags:
  - Hexo
categories:
  - 博客搭建
---

文章内容
```

此后，只需专注于 Markdown 内容的撰写即可。

# 部署到 GitHub Pages

由于 Hexo 最终生成的是静态 HTML 文件，因此可以直接使用 GitHub Pages 托管。创建仓库 `tamakara.github.io`，开启 Pages 功能后，博客地址为 `https://tamakara.github.io`，即可访问。

# 使用 GitHub Actions 自动部署

最初部署博客时，需要手动执行 `hexo generate` 并上传生成的文件。虽然博客不大，但每次修改文章都重复这些操作，多少有些繁琐。因此我引入了 GitHub Actions。

现在的流程变为：修改文章后执行 `git push`，GitHub 会自动拉取代码、安装 Node.js 环境、安装依赖、执行 Hexo 构建，并发布最新网页。

Workflow 配置如下：

```yaml
name: Hexo Deploy

on:
  push:
    branches:
      - main

jobs:
  deploy:

    runs-on: ubuntu-latest

    steps:

    - name: Checkout
      uses: actions/checkout@v5

    - name: Setup Node
      uses: actions/setup-node@v5
      with:
        node-version-file: ".nvmrc"
        cache: npm

    - name: Install dependencies
      run: npm ci

    - name: Generate
      run: npx hexo generate
```

这样，以后写完文章只需提交代码即可自动完成部署。

# 添加依赖自动更新

博客依赖了一些 npm 包。为了避免长期不更新带来的潜在问题，我添加了 Dependabot。

创建 `.github/dependabot.yml` 文件，配置如下：

```yaml
version: 2

updates:
  - package-ecosystem: npm
    directory: "/"
    schedule:
      interval: weekly
```

之后 GitHub 会自动定期检查依赖更新。

# 评论系统折腾记录

博客搭建完成后，我希望增加评论功能。最初选择的是 Gitment，一个基于 GitHub Issues 的评论系统。

但在配置过程中发现，Gitment 已经较长时间未维护，其依赖的 GitHub OAuth 流程（登录、获取 Access Token、调用 API）与当前 GitHub 的机制存在兼容性问题。实际使用时出现：

```
GET https://api.github.com/user
401 Unauthorized
```

无法正常获取用户信息。经过排查，确认 Gitment 所使用的 OAuth 处理方式已经不太适合现在的 GitHub，最终放弃继续使用。

---

# 使用 Giscus 替代 Gitment

后来我选择了 Giscus。Giscus 使用 GitHub Discussions 保存评论，相比 Gitment，它不需要服务器、数据库，也无需维护 OAuth，与 GitHub Pages 的定位更为匹配。

不过，原有的 Yilia Plus 主题并未直接支持 Giscus。因此我借助 Codex 辅助修改了主题代码：修改文章模板、增加 Giscus 配置、添加评论组件。最终成功将 Giscus 集成到博客中。
