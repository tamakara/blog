本博客的第一篇文章，记录一下自己从零搭建这个博客的完整过程。

最开始只是想拥有一个属于自己的博客，用来记录学习过程和技术笔记。但是购买服务器、域名、维护后端服务对于一个个人博客来说成本较高，因此最终选择了一套完全免费的静态博客方案。

整个过程也踩了一些坑，例如 Hexo 初始化时网络请求失败、Gitment 评论系统无法正常使用等，最后通过调整方案解决。

本文记录完整搭建流程以及过程中遇到的问题。

# 方案介绍

本方案适合像我一样：

- 想拥有自己的博客
- 不想购买服务器
- 不想维护后端服务

最终采用的技术方案：

```

              GitHub Actions

                       |
                       |

                       |
                       |

                GitHub Pages

                       |
                       |

                 用户访问博客

用户
```

# 安装 Hexo

Hexo 是一款基于 Node.js 的静态博客生成器。

它通过 Markdown 编写文章，然后将文章转换成静态 HTML 文件。

相比传统博客：

- 不需要数据库
- 不需要后端服务
- 部署简单
- 非常适合 GitHub Pages 这类静态托管平台

## 环境前置要求

首先确保本地环境已经安装：

- Node.js
- npm
- Git

检查版本：

```bash
node -v
npm -v
git --version
```

---

## 安装 hexo-cli

通过 npm 安装 Hexo 命令行工具：

```bash
npm install -g hexo-cli
```

查看版本：

```bash
hexo -v
```

---

## 初始化博客项目

创建博客：

```bash
hexo init blog
cd blog
```

安装依赖：

```bash
npm install
```

正常情况下 Hexo 会自动拉取初始化模板。

但是在实际操作过程中遇到了网络问题。

执行：

```bash
hexo generate
```

时出现：

```
fatal: unable to access xxx
Failed to clone hexo-starter
```

原因是 GitHub 网络连接不稳定，导致 Hexo 无法正常拉取：

```
https://github.com/hexojs/hexo-starter.git
```

解决方式：

手动拉取 starter：

```bash
git clone https://github.com/hexojs/hexo-starter.git
```

然后继续安装依赖：

```bash
npm install
```

最终完成 Hexo 初始化。

# 本地运行博客

生成静态页面：

```bash
hexo generate
```

启动本地服务器：

```bash
hexo server
```

访问：

```
http://localhost:4000
```

即可看到默认博客页面。

# 配置博客主题

Hexo 默认主题功能比较简单，因此选择了：

```
Yilia Plus
```

作为博客主题。

安装主题：

```bash
git clone https://github.com/JoeyBling/hexo-theme-yilia-plus.git themes/yilia-plus
```

修改根目录：

```yaml
_config.yml
```

配置：

```yaml
theme: yilia-plus
```

重新生成：

```bash
hexo clean
hexo generate
```

主题替换完成。

# 创建第一篇文章

Hexo 使用 Markdown 编写文章。

创建文章：

```bash
hexo new "我的第一篇文章"
```

生成：

```
source/_posts/
    我的第一篇文章.md
```

文章格式：

```markdown
---
title: 标题
date: 2026-07-27
tags:
---

文章内容
```

之后只需要编写 Markdown 文件即可。

# 使用 GitHub Actions 自动部署

最开始博客发布流程：

```
修改文章

↓

hexo generate

↓

上传文件

↓

部署
```

每次都需要手动操作。

因此加入 GitHub Actions，实现自动化部署。

最终流程：

```
git push

↓

GitHub Actions启动

↓

安装Node环境

↓

安装依赖

↓

Hexo生成静态文件

↓

部署GitHub Pages
```

Workflow：

```yaml
name: Hexo Deploy

on:
  push:
    branches:
      - main

jobs:
  deploy:

    runs-on: ubuntu-latest

    steps:

    - name: Checkout
      uses: actions/checkout@v5

    - name: Setup Node
      uses: actions/setup-node@v5
      with:
        node-version-file: ".nvmrc"
        cache: npm

    - name: Install dependencies
      run: npm ci

    - name: Generate
      run: npx hexo generate
```

配置完成后，只需要：

```bash
git push
```

即可自动完成博客更新。

# Node.js版本管理

为了避免本地和 GitHub Actions 使用不同 Node 版本，增加：

```
.nvmrc
```

内容：

```
24
```

然后 Actions 使用：

```yaml
node-version-file: ".nvmrc"
```

这样以后升级 Node 版本时，只需要修改一个文件。

# 使用 Dependabot 自动更新依赖

博客依赖：

- Hexo
- npm package
- 主题依赖

长期不更新可能存在安全问题。

因此启用 GitHub Dependabot。

创建：

```
.github/dependabot.yml
```

内容：

```yaml
version: 2

updates:
  - package-ecosystem: npm
    directory: "/"
    schedule:
      interval: weekly
    open-pull-requests-limit: 20
```

之后 GitHub 会自动检查依赖更新，并创建 Pull Request。

# 评论系统接入

## Gitment尝试

最开始计划使用 Gitment。

Gitment 的设计：

```
博客文章

↓

GitHub OAuth

↓

GitHub Issues

↓

保存评论
```

但是实际配置过程中遇到了问题。

Gitment 使用较老的 OAuth 流程：

```
Gitment.js

↓

cors-anywhere

↓

GitHub OAuth Token
```

由于 Gitment 长时间没有维护，现在 GitHub OAuth 流程已经存在兼容问题。

最终出现：

```
GET https://api.github.com/user

401 Unauthorized
```

无法正常获取用户信息。

---

# 使用 Giscus 替代 Gitment

经过分析后，决定更换方案。

最终选择：

```
Giscus
```

Giscus 基于 GitHub Discussions。

工作流程：

```
用户评论

↓

Giscus

↓

GitHub Discussions

↓

展示评论
```

优势：

- 不需要服务器
- 不需要数据库
- 不需要 OAuth Secret
- 与 GitHub 深度结合

由于 Yilia Plus 原主题没有 Giscus 支持，因此通过 Codex 辅助修改主题代码，将 Giscus 集成到文章页面。

修改内容：

- 增加 Giscus 配置项
- 修改文章模板
- 添加 Giscus script 加载
- 保留原主题结构

最终成功接入评论功能。
