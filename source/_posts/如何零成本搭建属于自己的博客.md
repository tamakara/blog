这是本博客的第一篇文章，记录一下搭建这个博客的完整过程。

其实很早以前，我就想拥有一个属于自己的博客。

我并不期待自己能够写出多么优秀、多么有深度的文章，也没有想着一定要通过博客获得什么收益。

我只是希望，在互联网这个巨大的空间里，能够拥有属于自己的一小片天地。

可以记录自己的学习过程，记录一些思考，也记录一路走来的成长。

## 为什么重新搭建博客

第一次接触博客是在高中之前。

我在高中的时候搭建过用 WordPress 博客

当时在网上购买了 Azure 学生认证账号，可以免费使用一年的云服务器。

有了服务器之后，我部署了 WordPress，也尝试修改主题、配置插件，把它当作自己的个人网站。

但是后来进入高中阶段，学习压力逐渐增加，没有太多时间继续维护。

服务器、网站、数据，最终都慢慢停止维护，之前积累的内容也随着时间丢失。

直到现在大三，重新开始学习新的技术，我又产生了搭建博客的想法。

这一次，我希望选择一种更加简单、长期可维护的方式。

我不想再花精力去维护：

- 不想处理服务器安全问题
- 不想维护 Linux 环境
- 不想担心数据库备份
- 不想为了一个博客长期支付费用

所以最终选择了：

> 静态博客 + GitHub Pages + 自动化部署

这种更加适合个人长期维护的方案。

---

# 方案选择

目前有很多搭建个人博客的方式：

- WordPress
- Halo
- Hugo
- Hexo
- Jekyll

经过考虑，我最终选择了 Hexo。

原因很简单：

Hexo 本身是一个静态博客生成器。

我只需要：

1. 使用 Markdown 编写文章。
2. 使用 Hexo 将文章转换成网页。
3. 将生成后的静态文件部署出去。

不需要数据库，也不需要后端服务。

对于一个个人博客来说，这种方式更加轻量。

最终使用的方案：

- Hexo：博客生成框架
- Yilia Plus：博客主题
- GitHub Pages：网站托管
- GitHub Actions：自动构建部署
- Giscus：评论系统

整个博客不需要购买服务器，也不需要购买域名，成本为 0。

# 安装 Hexo

Hexo 是一款基于 Node.js 的静态博客生成器。

它支持使用 Markdown 编写文章，然后生成完整的静态网站。

## 环境准备

首先需要安装：

- Node.js
- Git

检查环境：

```bash
node -v
npm -v
git --version
```

---

## 安装 Hexo

通过 npm 安装 Hexo 命令行工具：

```bash
npm install -g hexo-cli
```

查看版本：

```bash
hexo -v
```

---

## 初始化博客

创建博客目录：

```bash
hexo init blog

cd blog
```

安装依赖：

```bash
npm install
```

正常情况下，Hexo 会自动下载初始化模板。

但是实际过程中遇到了一个问题。

执行：

```bash
hexo generate
```

时出现网络错误，无法成功拉取：

```
https://github.com/hexojs/hexo-starter.git
```

由于 GitHub 网络连接不稳定，Hexo 初始化过程失败。

后来选择手动拉取仓库：

```bash
git clone https://github.com/hexojs/hexo-starter.git
```

然后重新安装依赖：

```bash
npm install
```

最终完成初始化。

---

# 本地运行博客

生成网页：

```bash
hexo generate
```

启动本地服务：

```bash
hexo server
```

访问：

```
http://localhost:4000
```

即可看到本地博客。

---

# 配置博客主题

Hexo 默认主题比较简单，因此选择了：

Yilia Plus。

安装主题：

```bash
git clone https://github.com/JoeyBling/hexo-theme-yilia-plus.git themes/yilia-plus
```

修改 Hexo 配置：

```yaml
theme: yilia-plus
```

重新生成：

```bash
hexo clean

hexo generate
```

之后博客页面替换成新的主题。

# 编写文章

Hexo 使用 Markdown 管理文章。

创建文章：

```bash
hexo new "文章标题"
```

生成文件：

```
source/_posts/
```

文章结构：

```markdown
---
title: 文章标题
date: 2026-07-27
tags:
  - Hexo
categories:
  - 博客搭建
---

文章内容
```

之后只需要专注写 Markdown 即可。

# 使用 GitHub Actions 自动部署

最初部署博客时，需要手动：

```bash
hexo generate
```

然后上传生成后的文件。

虽然博客很小，但是每次修改文章都重复操作比较麻烦。

因此加入 GitHub Actions。

现在流程变成：

修改文章后：

```bash
git push
```

GitHub 会自动：

1. 拉取代码。
2. 安装 Node.js 环境。
3. 安装依赖。
4. 执行 Hexo 构建。
5. 发布最新网页。

Workflow：

```yaml
name: Hexo Deploy

on:
  push:
    branches:
      - main

jobs:
  deploy:

    runs-on: ubuntu-latest

    steps:

    - name: Checkout
      uses: actions/checkout@v5

    - name: Setup Node
      uses: actions/setup-node@v5
      with:
        node-version-file: ".nvmrc"
        cache: npm

    - name: Install dependencies
      run: npm ci

    - name: Generate
      run: npx hexo generate
```

这样以后写完文章，只需要提交代码即可。

# 添加依赖自动更新

博客依赖了一些 npm 包。

为了避免长期不更新，添加 Dependabot。

创建：

```
.github/dependabot.yml
```

配置：

```yaml
version: 2

updates:
  - package-ecosystem: npm
    directory: "/"
    schedule:
      interval: weekly
```

之后 GitHub 会自动检查依赖更新。

# 评论系统折腾记录

博客搭建完成后，我希望增加评论功能。

最开始选择的是 Gitment。

Gitment 是一个基于 GitHub Issues 的评论系统。

但是配置过程中发现它已经比较久没有维护。

它依赖旧的 GitHub OAuth 流程：

- OAuth 登录
- 获取 Access Token
- 调用 GitHub API

实际使用时出现：

```
GET https://api.github.com/user

401 Unauthorized
```

无法正常获取用户信息。

经过排查，发现 Gitment 使用的一些 OAuth 处理方式已经不太适合现在的 GitHub。

最终放弃继续维护 Gitment。

---

# 使用 Giscus 替代 Gitment

后来选择了 Giscus。

Giscus 使用 GitHub Discussions 保存评论。

相比 Gitment：

- 不需要服务器
- 不需要数据库
- 不需要维护 OAuth
- 与 GitHub Pages 更匹配

但是原来的 Yilia Plus 主题并没有直接支持 Giscus。

因此通过 Codex 辅助修改主题代码：

- 修改文章模板
- 增加 Giscus 配置
- 添加评论组件

最终成功将 Giscus 集成到博客中。
